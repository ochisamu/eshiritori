# 絵しりとり 音声対戦相手の要件

作成日: 2026-10-31（日本時間）
対象: ローカル実行と同一LAN内で利用する、OpenAI APIキー方式の追加機能
対応する設計: [音声対戦相手の設計](live-opponent-api-design.md)
別スレッドへの依頼: [開発依頼文](live-opponent-development-request.txt)

## 1. 目指す体験

同じ盤面を見て、一緒に絵しりとりを遊んでいる相手を作る。相手はプレイヤーから話しかけられなくても、探している時、着手した時、面白い読みを発見した時などに自分から反応する。プレイヤーは自然な言葉で雑談し、ヒントや直前の読みの説明を聞ける。

自然さと変化を主要な品質要件とする。イベントごとの固定セリフを順番に再生する体験にはしない。盤面、直前のやり取り、今回の発見を材料に発言を生成し、沈黙や聞く時間も取る。ゲームに対して正確であることを、言い回しの新しさより優先する。

## 2. ユーザーが決めたこと

| ID | 決定 |
| --- | --- |
| U01 | OpenAI APIキー方式で開発する。Codexログイン・app-server方式は今回の対象にしない。 |
| U02 | まずはホスティングせず、利用者がローカルで起動する版を配布する。 |
| U03 | ホストPCだけでなく、同一LAN内の端末からも利用できるようにする。 |
| U04 | 話しかけられるのを待たず、盤面・相手ターン・探す仕草などに合わせて自発的に話す。 |
| U05 | 会話でヒントを聞けるようにする。 |
| U06 | 判断モデルを利用可能な構成にする。Live、推論用LLM、Decisionsの役割を分ける。 |
| U07 | 一緒にゲームをしているような体験と、固定文言ではない変化・自然さを重視する。 |

以降の初期値・優先順位は、この決定を具体化する実装方針である。数値は設定で調整できるようにし、実測に基づく変更を検証報告に残す。

## 3. 既存ゲームの基準

実装開始時にREADMEと実コードを再確認する。別スレッドで更新される可能性があるため、本書作成時点のコードだけを固定基準にしない。

- React / TypeScript / Vite、Node.js 22.12以上。既存配信は tools/serve.mjs、ポート4173。
- 24枚の盤面、交互対戦・ひとり・早押し、補充、発見・図鑑、保存・再挑戦がある。
- 現行ルールは alternating-24-race-score-v6。手詰まりは盤面クリア。早押しは現在盤面の得点で勝敗を判定する。以前の文字を変えるつなぎ直しは廃止済み。音声追加で復活させない。
- 現在のREADMEは1,024枚・3,122読み。件数をプロンプトやテストへ固定しない。
- ヒントは1対戦3段階。第1段階は絵の説明、第2段階は種類・文字数・穴あきの読み、第3段階は答え。開き直しは追加消費しない。
- 現行コードではヒント第3段階もHINT経路であり、図鑑の答え表示で使うREFERENCEとは別。音声だけで参照区分を変更しない。時間なしは練習扱いでランキング登録しない。
- 相手の見た目は3種類ある。現在の対戦画面は名前を表示しない。常設の説明や名前で盤面を狭めない。
- CPUの着手、採点、発見、勝敗、時間、補充、辞書の採否は既存エンジンが決める。

過去の「外部API不要」は標準ゲームに維持する。音声モードだけは、明示的な開始操作で外部APIを利用する追加仕様とする。

## 4. 初期版の範囲

### 4.1 必須

- 標準ゲームはAPIキーなしで従来どおり遊べる。
- 音声モードは交互対戦の時間なし、および時間なしの補充に対応する。
- 回答はタップ・既存の入力操作で行う。音声での回答確定は後続段階。
- 一つのホストPCで、一つのゲームに一つの音声セッションを接続する。ホストまたはLAN端末のどちらでも利用できる。
- 接続開始・終了、マイク入力のオンオフ、相手の音声出力のオンオフ、字幕、発話頻度設定を提供する。
- 対局に合わせた自発発言、自然な会話、段階的なヒント、直前の読みの説明に対応する。
- Decisionsによる表情・仕草の選択を実装し、オンオフできる。利用不可・失敗時も会話とゲームは継続する。
- 会話を切断しても進行中の盤面・発見・保存を失わない。
- 接続時間、モデル、接続状態、利用量の把握に必要な表示を備える。

### 4.2 後続段階に回すもの

公開ホスティング、課金サービス、運営者によるAPI代負担、Codex/app-server、ChatGPTログイン、複数の同時音声ゲーム、同じ盤面の端末間同期、対人オンライン対戦、音声だけでの回答確定、未登録語のLLM採用、辞書改訂、長期の人物記憶は初期版の対象外。

時間あり・早押し・ひとりは従来どおり遊べる。初期版の音声対象外であることを設定に表示する。後続対応でも、会話を理由にゲーム時間を自動延長しない。

## 5. 会話体験

### 5.1 盤面に結び付いた自発発言

以下は発言機会であり、毎回話す義務ではない。例文は意図の例であって固定セリフではない。

| イベント | 期待する反応 | 開示してよい情報 |
| --- | --- | --- |
| 新しい盤面 | 絵の顔ぶれを眺めて一言 | 見えている絵と現在の文字 |
| CPU探索開始 | 「『ら』かあ……どこかにあるかな」のような短い独り言 | 現在の文字・見えている絵。未確定の答えは言わない |
| CPU着手確定 | 確定した読みを自然に伝える | 確定済みの札・読み・次の文字 |
| プレイヤーの回答 | 相づち、反応、または静かに見守る | 確定済みの読み |
| 新しい裏読みの発見 | 発見の具体的な点への驚き | 今回確定した読みと承認済みの理由 |
| 盤面クリア・勝敗確定 | 結果への反応、短い振り返り | 確定した結果と今回の出来事 |

- 探索演出の scan / compare / locked を利用できる。ただしカーソルが見た札を正解候補と断言しない。
- プレイヤーの思考中は静かに見守るのを基本にする。勝手なヒントや回答の催促を繰り返さない。
- 発話生成・再生のためにCPU着手、回答表示、次の手番を遅らせない。
- 遅れた探索発言は着手後に再生しない。古い盤面について現在形で話さない。

### 5.2 自然さと変化

- 通常の発言はモデルが状況から生成する。固定文言のローテーションや語尾だけの差し替えを中核にしない。
- 同じイベントでも、観察する点、言い回し、発話の有無が変わる。
- 直近の発言を参照し、同じほめ方・問いかけ・出だしを繰り返しにくくする。
- 今回の発見や直前の会話をセッション内で覚え、後から自然に触れられる。実際に起きたことだけを記憶する。
- すべての回答をほめない。相づち、驚き、独り言、無言を使い分ける。
- 毎回質問で締めない。相手の返事を待つ演出でゲーム操作を止めない。
- 一緒に探す口調を基本とし、教師役、過剰な実況、長い講評へ偏らない。
- プレイヤーが話し始めたら聞く。言い直しや否定を無視して操作しない。
- 一貫した性格を保つ。まず共通の自然な性格で完成させ、見た目別の性格・声は拡張可能にする。
- 発話頻度は「静か／ほどほど／よく話す」。「静か」でも質問・要求されたヒントには応答する。
- 障害時の状態案内だけは固定文言でよい。通常体験を固定文言だけで代替して完了にしない。

### 5.3 ヒントと読みの説明

- 「ヒントちょうだい」「もう少し」「もう一度」「答えを教えて」を区別する。
- 画面と音声の段階・使用回数・答え参照の扱いを共有する。
- 初回は第1段階。現在のヒントの再表示・再読み上げは消費しない。明確な追加要求のときだけ次へ進む。
- 「答えを教えて」は第3段階への要求。必要な段階の消費・参照状態は既存画面と同じ規則で適用する。
- 「答えは言わないで」「ヒントはいらない」「ヒントって何？」でヒントを消費しない。
- 決定前の文字起こし断片では段階を進めない。曖昧なら短く聞き返す。
- 既存の絵の説明、readingHint、承認済みの説明を根拠にする。新しい正解・裏読みを作らない。
- 下位段階の生成入力に、上位段階の答えや全合法手一覧を含めない。
- 現在の段階の範囲で自然に言い換えられる。新しい手掛かりを勝手に足さない。
- 「今のはどういう読み？」には直前の確定済みの読みを説明する。図鑑の未発見語一覧を開示しない。

## 6. 責任分担

| 構成要素 | 責任 |
| --- | --- |
| 既存エンジン | 合法性、CPU着手、採点、勝敗、ヒント段階、発見、保存 |
| GPT-Live | 双方向音声、会話、自発発言の自然な表現 |
| 推論用LLM | ヒント・説明・質問の処理。限定されたゲーム用ツールを利用 |
| Decisions | 定義済み候補から表情・仕草を選択 |
| 接続サーバー | キー保持、接続認可、状態整理、呼び出し上限、古い結果の破棄 |

Decisionsの結果は確率的な提案として扱う。モデル出力だけで着手・勝敗・ヒント消費を確定しない。発話意図へ拡張しても変更操作は共通の実行経路で検査する。

## 7. ローカル実行とLAN

- キーはホストPCの環境変数またはローカルの .env に設定する。LAN端末から入力・取得できない。
- LAN端末の利用料もホストのキーへ計上されると接続前に表示する。
- ローカルはlocalhost。LANモードは明示的に有効化する。
- LAN音声は端末が信頼する証明書を使ったHTTPS/WSSとする。接続先と証明書のSANを一致させる。
- QRコードで接続URLを案内し、ペアリングコード確認後に接続を許可する。
- 未認可、別Origin、期限切れのAPI・WebSocket要求を拒否する。
- 初期版は1台の音声接続。2台目には使用中と表示し、既存接続を勝手に切らない。
- ホスト停止、接続切れ、ページ終了時に音声接続を閉じる。切断してもゲームは続けられる。
- WSLとネイティブOSの起動経路を区別する。LAN到達性、証明書、ファイアウォールに必要な手順を文書化する。

## 8. 利用量とプライバシー

- 明示的な開始前に課金音声セッションを作らない。画面を開くだけではOpenAIへ接続しない。
- マイク送信中、入力ミュート、切断済みを区別する。
- ミュートと切断は別操作。ミュート中も接続は課金対象であることが分かるようにする。
- 接続時間と各モデルの利用量を別集計する。推定料金には単価設定日と推定であることを示す。
- 接続時間、バックエンド呼び出し数、Decisionsの頻度をホスト側で制限する。
- 音声・全文の文字起こしは既定でディスクへ保存しない。デバッグ保存はホストの明示設定時だけ。
- キー、Cookie、SDP、音声、会話本文を通常ログへ出さない。通常ログはID・種別・遅延・利用量・エラーコード中心。
- キー、会話、接続情報をセーブデータ、再挑戦コード、配布物、PWAキャッシュへ含めない。
- ローカル実行でも、音声・必要な会話・限定した盤面情報をOpenAIへ送ることを説明する。

## 9. 障害と互換性

- キー不正、モデル権限なし、利用枠、429、通信切断、マイク拒否、HTTPS不備を区別する。
- Live障害時は音声を終了し、タップ操作のゲームを継続する。
- Decisions障害時は既存の表情へ戻す。無限再試行しない。
- 推論モデル障害時も既存の画面ヒント・説明は使える。
- 再接続で着手やヒント消費を再実行しない。会話だけ再開し、現在状態を送り直す。
- 音声のオンオフでCPU選択・乱数・保存・再挑戦を変更しない。
- 画面固定、キーボード操作、消音、動きを減らす設定を維持する。

## 10. 受け入れ条件

| ID | 合格条件 |
| --- | --- |
| A01 | APIキーなし・外部API遮断で標準ゲームが動き、既存の操作・保存を維持する。 |
| A02 | ホストPCでLiveの双方向日本語会話と字幕が動く。 |
| A03 | 別のLAN端末でHTTPS・ペアリング・マイク・会話が動く。実端末と証明書条件を記録する。 |
| A04 | 開始前に課金APIが呼ばれず、停止時の終了と利用量を確認できる。 |
| A05 | 話しかけなくても探索・着手・発見・結果の適切な場面で自発発言する。 |
| A06 | 音声待ちでゲームを遅らせず、遅れた探索発言を捨てる。 |
| A07 | 割り込み・言い直し・否定に対応し、同じ要求を二重実行しない。 |
| A08 | ヒントの初回・追加・再読み上げ・答え要求で、画面と回数・段階・参照状態が一致する。 |
| A09 | ヒント不要・雑談・途中の発話だけでは消費しない。 |
| A10 | 未確定の着手、未発見語一覧、補充予定、証明経路を会話へ送らない。 |
| A11 | Decisionsで表情が変わり、オフ・権限不足・失敗時は既存表情へ戻る。 |
| A12 | 古い判定を後の手番・別の接続へ適用しない。 |
| A13 | 2台目、未認可、別Originを拒否し、キーがブラウザ・ログ・配布物に現れない。 |
| A14 | 一時停止、再開、再挑戦、次の盤面、切断・再接続で状態とヒント消費が壊れない。 |
| A15 | 現行の手詰まりクリア・早押し得点ルールを維持し、旧つなぎ直しを復活させない。 |
| A16 | 対戦画面の盤面を狭めず、ページ全体の縦スクロールを増やさない。 |
| A17 | 通常発言が実際の生成結果であり、固定文言だけの代替ではない。 |
| A18 | 複数盤面で発言の変化、正確な会話・発見の記憶、聞く時間を確認できる。 |

### 自然さの確認

実APIで3盤面・10分程度を目安に試遊する。これは初期評価の提案値であり、料金上限内で行う。実施できない場合は未検証と報告する。設定・実装時間を試遊時間へ加算しない。

同じ文字から探す場面、裏読み発見、ヒント拒否、説明要求を複数回試す。状況適合、繰り返し、発話長、割り込み、沈黙を人が評価する。言い回しが違うだけでは合格にしない。試験用に作った発言だけを公開検証報告へ引用する。

## 11. 後続の候補

キャラ別の性格・声、発見の振り返り、選択した絵についての会話、協力モード、音声回答の確認操作、時間あり・ひとり・早押しへの対応、複数セッション、Decisionsによる意図分類とLiveネイティブトリガーの比較。
